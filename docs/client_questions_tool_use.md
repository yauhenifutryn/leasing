# Вопросы по интеграции инструментов голосового помощника

Я начинаю разработку инструментов для голосового помощника: расчёт платежей, отправка СМС с графиком, и в дальнейшем передача на специалиста через AMO CRM.

Ниже вопросы, сгруппированные по сервисам. Срочность указана для каждого блока.

---

## 1. Калькулятор платежей (нужно до начала разработки)

API: `https://personal.mikro-leasing.by/calculator/api/`

1.1. **Авторизация**: Bearer-токен для доступа к API. Это статический ключ или требуется OAuth/обновление токена? Кто выдаёт токен?

1.2. **Лимиты запросов**: Есть ли ограничения на количество запросов? Ожидаем небольшой объём (50-100 запросов в день), но нужно знать заранее.

1.3. **Ошибки**: Что возвращает API при некорректных параметрах? HTTP 400 с телом ошибки или другой формат? В документации показаны только успешные ответы.

1.4. **Формат значений параметра `subject`**: В описании указано "Легковые автомобили" (множественное число), а в примерах ответов "Легковой автомобиль" (единственное). Какую форму принимает API на вход?

1.5. **Поведение при отсутствии подходящих условий**: Если переданные параметры не подходят ни под одно условие, что возвращает `/1.0/calculate/`? Пустой результат, ошибку, или ближайшее совпадение?

1.6. **Стабильность**: Это продуктивный сервер или тестовый? Есть ли окна обслуживания, когда API может быть недоступен?

## 2. СМС-сервис (нужно до реализации отправки СМС)

Сервис: `https://dev.sms-assistent.by/`

2.1. **Учётные данные**: Кто предоставляет логин/токен для API? Есть ли тестовая среда (sandbox) для отладки без реальной отправки?

2.2. **Формат API**: REST? Какой эндпоинт для отправки, метод авторизации, формат запроса? Или достаточно изучить публичную документацию на dev.sms-assistent.by?

2.3. **Имя отправителя**: СМС будет приходить от "MikroLeasing" (буквенное имя) или от номера телефона? Буквенные имена обычно требуют предварительной регистрации у провайдера.

2.4. **Длина сообщения**: Есть ли ограничения на длину? Полный график на 36 платежей займёт 500-700 символов (3-4 сегмента СМС).

2.5. **Существующие наработки**: Упоминалось, что уже есть наработки по интеграции с СМС-сервисом. Можно ли получить доступ к этому коду (желательно файлом)? Даже частичная реализация ускорит работу.

## 3. AMO CRM (нужно к началу второй фазы, не срочно)

API: `https://www.amocrm.ru/developers/content/crm_platform/api-reference`

3.1. **Учётные данные и адрес**: URL инстанса AMO CRM (обычно `company.amocrm.ru`). Метод авторизации: OAuth 2.0 с долгоживущим токеном или API-ключ?

3.2. **Поля для создания лида**: В какую воронку и с каким статусом должны попадать новые лиды? Какие кастомные поля настроены (телефон, имя, тема обращения, и т.д.)?

3.3. **Существующие наработки**: Упоминался подрядчик и наработки от альтернативного проекта. Можно ли получить доступ к коду или хотя бы к описанию используемого API-контракта?

3.4. **Дубликаты**: Если один и тот же клиент звонит дважды и оба раза передаётся специалисту, создавать два лида или обновлять существующий?

В идеале если можно сдать отдельную тестовую таблицу к которой у системы будет доступ чтобы она туда могла заносить и получать данные, т.е. Не добавить доступ к production CRM базе.
